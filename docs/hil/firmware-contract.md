# Firmware contract (what the rig needs from the firmware sessions)

Negotiable: firmware sessions answer per item in their `docs/SESSION_NOTES.md` ("FW-0x: accepted / declined because … / changed to …").

## IT1

| ID | Owner | Requirement | Rationale | Status today |
|---|---|---|---|---|
| FW-01 | both | Keep the pins the rig uses on nucleo_f767zi free, and keep the catalog stable. Do not use PD4, PD5 or PD6 (USART2), PG0-PG3, PE10, PE12, PE14 or PE15. Do not touch NRST or E5V. Keep the console and shell on USART3 PD8/PD9 at 115200. Keep the 17 uc,io-channels names and their order in firmware/boards/io/nucleo_f767zi.dtsi: append only. | The HIL snippets (hil, hil-io) and the hand-wired harness use these pins. uc_io assigns channel ids in devicetree order, so inserting a channel renumbers every channel after it and silently rewires the rig. | Holds at BACnet 2161be7 and MQTT d9cae9e. An edtlib pin scan with both apps and both snippets found no conflicts. |
| FW-02 | both | Keep identity learnable: no forced MAC on nucleo_f767zi (no local-mac-address or zephyr,random-mac-address), so the MAC stays 02:80:E1 plus the low 3 bytes of crc32_ieee over the hwinfo UID; DHCPv4 client on by default; BACnet default instance 260001, overridable by device.json; MQTT client id 'z' + base32(UID) when CONFIG_APP_MQTT_CLIENT_ID is empty; the retained MQTT info keeps hwid, mac and fw. | B7. dnsmasq reserves 192.0.2.10 on the real MAC, which is recorded once in bench.yml. Captures and the release-tier identity checks key on it. R-07 recomputes the MAC from the UID before every flash (D29). | Holds on both. Neither F767 overlay sets a MAC property. MQTT info carries hwid, mac and fw since 0.3.0. |
| FW-03 | both | Keep these console lines stable (the text after the module prefix): 'formatting /lfs' (BACnet), and the version/board banners 'BACnet-uc <ver> on <board>' and 'MQTT over Ethernet + TLS on <board>'. Rename or reformat them only after a SESSION_NOTES entry. No other app line is frozen. | PERS-01 and PERS-03 fail on 'formatting /lfs', the only console line used as a criterion in the release tier. The banners are recorded for diagnosis. The instrumented tier waits on lib/hil's own HIL-BOOT/HIL-READY lines, so the apps need no other stable lines. | All three lines are present today (main.c, uc_storage.c, mqtt_app.c). |
| FW-04 | bacnet | The default nucleo_f767zi build of firmware/ must link. Until it does, keep the documented workaround valid: chosen uc,app-pool = &dtcm with CONFIG_UC_APP_POOL_SIZE=98304. | FW-05 | both | No image the rig flashes may halt forever on a fatal error. | FW-06 | both | Before pushing, announce on your branch's SESSION_NOTES any change to: nucleo_f767zi overlays or board conf files, flash partitions or MCUboot enablement, the FW-03 lines, default network behaviour (DHCP, UDP 47808, UDP 1337, TCP 8883), the SMP and MQTT interfaces, the APP_MQTT_* site symbols on the D24 allowlist (broker hostname, CA and client-auth files), the fields of schemas/{device,io,apps}.schema.json that rig_config pushes, and the bacnet_uc_harness.smp client API that hilrig reuses. | The nightly run builds the branch tips. An unannounced change shows up as a HIL failure with no context. rig_config, the site builds and the reused SMP client depend on exactly these interfaces. The HIL session reads your notes before each triage. | Informal today. Both sessions already keep SESSION_NOTES. |

## IT2

| ID | Owner | Requirement | Rationale | Status today |
|---|---|---|---|---|
| FW-07 | bacnet | For MS/TP on F767, the HIL proposes USART2: TX PD5 (CN9-6), RX PD6 (CN9-4), DE PD4 (CN9-8), with hardware DE: de-enable, de-assert-time = de-deassert-time = 16. uart_configure() only through get-modify-set with UART_CFG_FLOW_CTRL_RS485. DE and /RE tied, with a 10k pull-down on the DE net. The HIL snippet provides this node now; it moves into firmware/boards when MS/TP lands. P2 wiring is to be agreed later: LPUART-only FC2 with nxp,rs485-mode, or a GPIO DE on D11. Please answer accept/decline and when Phase 3 starts: the HIL builds its MS/TP bench only then (D34). | The roadmap plans USART6 on D0/D1 with GPIO DE on PD15. The F7 USART6 hardware-DE pins (PG8/PG12) are morpho-only, and GPIO DE timing depends on TX-complete ISR latency, which is exactly what MSTP-05 measures. USART2 supports DEM, and usart2_de_pd4 is push-pull in hal_stm32 fc11896d. If you decline, the rig rewires U1 with a jumper selector. | Not implemented: MS/TP is roadmap Phase 3, and there is no RS-485 port code. |

| FW-10 | bacnet | Decide the release management posture: SMP over DTLS (CONFIG_MCUMGR_TRANSPORT_UDP_DTLS) or an overlay-production.conf that disables GRP_SHELL and restricts GRP_FS. | FW-11 | bacnet | For MCUboot images, the rig flashes the sysbuild build dir (MCUboot + signed slot0). HIL images are signed with the repo test key, or with a HIL test key you name. SEC-01 needs to know which overlay-mcuboot.conf symbols belong to that artifact. | sysbuild scenarios exist for f767 (scratch swap) and mcxn947 (swap-using-offset). They have not been run on hardware. |
| FW-12 | mqtt | Choose a certificate time-validation policy. If enabled, use the 4.4.2 symbols CONFIG_SNTP, CONFIG_NET_CONFIG_CLOCK_SNTP_INIT, CONFIG_NET_DHCPV4_OPTION_NTP_SERVER, CONFIG_NET_CONFIG_SNTP_INIT_SERVER_USE_DHCPV4_OPTION and CONFIG_MBEDTLS_HAVE_TIME_DATE, and one of two init paths: either the app calls net_init_clock_via_sntp() after the lease (declaring the extern itself, since no public header declares it), or it adopts NET_CONFIG_SETTINGS plus NET_CONFIG_AUTO_INIT and drops APP_DHCPV4. Document what happens when NTP is unreachable (no forever-blocked MQTT). | The expired-certificate case in TLS-01 and TIME-01 depend on this policy. The symbols alone do not sync the clock: net_init_clock_via_sntp() is called only from net_config init.c, which is compiled only with NET_CONFIG_SETTINGS, while APP_DHCPV4 requires !NET_CONFIG_SETTINGS. | HAVE_TIME_DATE is off, and prj.conf documents that dates are not checked. |
| FW-13 | both | Provide a native_sim TAP variant (CONFIG_ETH_NATIVE_TAP; IP from DHCP or the overlay) next to NSOS, so SIL can run BACnet/IP broadcast tests in netns lan-a. | NSOS passes no SO_BROADCAST, so Who-Is and BBMD scenarios cannot run on it. | Both apps build native_sim with NSOS. |
| FW-14 | bacnet | MCXN catalog analog configuration: set &vref regulator-initial-mode = NXP_VREF_MODE_HIGH_POWER, as the Zephyr adc_dt sample does.
